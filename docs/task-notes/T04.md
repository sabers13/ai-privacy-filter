# T04 task notes

## Scope

The seeded synthetic enquiry corpus and its generator. No detection, no model
call, no network access.

## Decisions

- **Generator.** `data/make_synthetic.py` builds every record through a small
  `Builder` that appends text and records the start/end offsets at the same time.
  A gold span therefore cannot drift from the text: `text[start:end] == span.text`
  holds by construction, including the hard-case IBAN that contains a line break.
- **Seed and determinism.** One `Faker("de_DE")` instance is seeded once and then
  drives every value in a fixed call order. The generator writes `dev.jsonl`,
  `test.jsonl` and `README.md`; no timestamps or set iteration order enter the
  output, so the same seed and Faker version write byte-identical files.
- **Stratification.** Record *i* takes category `i % 5` and style `i % 7`, so all
  35 category/style combinations appear in both splits, categories are exactly
  balanced and style counts differ by at most one. Urgency follows a fixed cycle
  of about 60 % NORMAL, 20 % HIGH and 20 % LOW.
- **Urgency labels.** Each body variant is tied to its label. HIGH has an explicit
  deadline (`bis spätestens …`, `Frist endet …`, `läuft morgen ab`) or a complaint
  (`sehr unzufrieden`, `inakzeptabel`); LOW says `Es eilt nicht`, `keine Eile`,
  `Kein Stress` or `unverbindlich`; NORMAL has none of those cues. A test asserts
  exactly that.
- **Categories.** Every body names the category cue in the first sentence
  (`Angebot`, `Fehler im Kundenportal`, `bewerbe`, `Kooperation`, `allgemeine
  Frage`), and the subject repeats it where the style has a subject.
- **Hard cases.** `hard_cases` combines a surname that is also a common noun
  (`Berg`, `Wolf`, `Fuchs`, …), a company name built from that surname, an IBAN
  broken after the first half of its groups, and one of three odd phone formats.
  The surname inside the company name is annotated only as ORG, not as PERSON.
- **Organisations.** Invented, company-neutral names rather than Faker companies,
  so the corpus cannot accidentally name a real employer. Faker supplies names,
  streets, postcodes, cities, phone numbers, e-mail addresses and IBANs.
- **Seed bump.** Seed `20261027` produced one forbidden-scan hit in the test
  split, and `20261028` produced another. The corpus was regenerated with
  `20261029`, which scans clean; `data/synthetic/README.md` records the final seed
  and the note `seed changed: scan hit`. The matched words were never printed or
  written into the repository.

## Counts (seed 20261029)

- dev 80 records, test 160 records.
- Test gold spans: PERSON 252, EMAIL 206, PHONE 160, ADDRESS_STREET 137,
  POSTCODE_CITY 137, ORG 114, IBAN 68. All per-type minimums are met.
- `data/synthetic/README.md` carries the per-style, per-category, per-urgency and
  per-type tables for both splits.

## Deliberately absent

- No URL, VAT_ID or DATE_OF_BIRTH spans yet: the T04 brief sets no minimum for
  them, and none of the styles need them.
- No real personal data, no GermEval row, no live LLM call, no remote, no push.

## Verification

- `uv run python data/make_synthetic.py --seed 20261029` (deterministic output).
- `uv run pytest tests/test_synthetic.py`: byte-identical regeneration, committed
  files regenerate from the documented seed, all spans slice exactly, per-type
  minimums, stratification and urgency cues.
- `scripts/scan_forbidden.py --root data/synthetic` with `AIPF_FORBIDDEN_FILE`
  loaded: clean at seed 20261029.
- `make lint test`, gitleaks, and the full forbidden scan before commit.
