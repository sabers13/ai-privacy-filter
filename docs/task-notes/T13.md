# T13 task notes

## Scope

The local n8n review workflow, its compose stack, the headless end-to-end check
and the canvas screenshot. T13 consumes the T08 service contract and the T12
triage implementation; it does not change detection, pseudonymisation or the
triage prompt.

## Decisions

- **Two gate calls, one mapping.** `/process` deliberately returns no ticket.
  The workflow calls `/redact` first for the ticket, then `/process`, then
  `/restore` with the reply draft. Redaction is deterministic for the same
  text, so the ticket from `/redact` restores the placeholders the model saw.
- **The webhook answers immediately.** A Respond-to-Webhook node in front of the
  Wait form was tried first; n8n kept the HTTP connection open while the
  execution waited at the form. The webhook now uses its immediate response and
  the workflow writes the form URL to `/data/pending/<id>.json`. The harness
  reads that file; a person would open the same URL from n8n. The final result
  still goes to `/data/out/<id>.json`.
- **One pending record per outcome.** The guard-failure branch writes a pending
  record with `status: blocked` and the leaked types, with no form URL and no
  model call. A 501/5xx gate answer is `gate_error`, not a guard block, so a
  broken backend cannot masquerade as a privacy decision.
- **Pinned image by tag and digest.** `docker.io/n8nio/n8n:2.45.4` plus its
  manifest-list digest. The Docker Hub mirror was used because the n8n registry
  rate-limited this host; the digest is the same one `stable` resolved to.
- **n8n file access is narrowed, not opened.** The file nodes need `/data/out`
  and `/data/pending`, so `N8N_RESTRICT_FILE_ACCESS_TO` names exactly those two
  directories. `N8N_BLOCK_FILE_ACCESS_TO_N8N_FILES=false` alone is not enough:
  the default allowlist is `~/.n8n-files`.
- **Environment access is explicit.** The workflow reads `AIPF_GATE_URL` and
  `AIPF_BACKEND` through `$env`; `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` is set on
  this local instance. No secret is in the export or the compose file.
- **Owner setup is deterministic.** The throwaway owner password is the private
  environment value; if n8n's policy lacks an uppercase letter, a lowercase
  letter, a digit or a symbol, the harness appends the missing class for both
  setup and login. The appended value is never printed.
- **Import is followed by a stop/start, not a restart.** n8n loads the active
  version only at process start. A restart left the old version serving the
  production webhook for a few seconds; stopping and starting removed that
  window.
- **Private podman socket.** `docker-compose` 1.29 has no podman driver and this
  host has no usable Docker socket. The harness starts `podman system service`
  on a socket inside its own temporary directory and points `DOCKER_HOST` at
  it. It never touches a shared socket.
- **Dev split only.** The five enquiries are the first five records of
  `data/synthetic/dev.jsonl`, so the end-to-end check does not consume a
  test-split number fixed by `METHOD.md`.
- **Approval mix.** The e2e uses approve, edit, approve, reject, approve so all
  three decisions are written. A rejected record keeps the restored draft and
  writes `final_reply: null`.

## Deliberately absent

- No remote, no push, no PR, no hosted n8n, no deployed endpoint.
- No credentials in the workflow, no `.n8n-data` in git.
- No test-split number, no claim about detection quality, no legal-compliance
  claim. The filter pseudonymises; it does not make text anonymous.
