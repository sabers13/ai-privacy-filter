# T02 task notes

## Scope

Detection core only: `detect.detect(text, *, profile="balanced") -> list[Span]`
and the German recognizers under `src/ai_privacy_filter/recognizers/`.
Pseudonymisation, the guard, triage, the HTTP service and the CLI stay stubs.

## Decisions

- **Engine.** Presidio `AnalyzerEngine` with `NlpEngineProvider` configured for
  `de_core_news_lg` and `supported_languages=["de"]`. One spaCy pipeline is
  loaded and shared by both profiles; only the recognizer registry and the score
  threshold differ, so switching profile does not load a second model.
- **Recognizer set.** spaCy NER (PERSON, ORGANIZATION), Presidio email and URL
  patterns, and local German recognizers for phone, IBAN, postcode+city, street
  and house number, VAT ID, date of birth, name context, first names and
  organisations with a legal form. Every custom recognizer reports our entity
  names; only spaCy's `ORGANIZATION` and Presidio's `EMAIL_ADDRESS` are mapped at
  the edge.
- **Person span convention.** A person span covers the mention the way T04's
  synthetic gold data annotates it: optional `Herr`/`Frau`, academic titles
  before the name and post-nominal titles such as `B.Sc.` or `MBA.`. A title
  without a name is not a span, and `Hallo Konstantin` is trimmed to
  `Konstantin` because spaCy includes the greeting word. Forwarded-mail headers
  ("Weitergeleitete Nachricht") that spaCy labels as PERSON are dropped.
- **Context in the recognizer, not in Presidio's enhancer.** German inflection
  makes lemma-based boosting hard to test, and some entities must only exist when
  context exists (a birth date, a name after a salutation). The shared
  `GermanRecognizer.context_hit` searches a character window for word-anchored
  cues and adds a fixed boost. A date of birth without a cue is dropped, not
  scored lower.
- **Patterns avoid the obvious look-alikes.** Phone numbers do not allow dots
  between groups, because `12.03.1985` would otherwise match; dates are only
  accepted with a birth-date cue; postcodes are range-checked; VAT IDs need
  exactly nine digits; IBANs need the mod-97 checksum in both profiles. A VAT ID
  directly after `DE` is not reported as a phone number.
- **Merge rule.** Rank by score, then span length, then entity priority, then
  start, end and source; keep the best-ranked span and drop overlapping ones;
  return sorted by position. This makes `Bäckerei Weber GmbH` an ORG rather than a
  PERSON, keeps an email over the URL inside it, and gives a deterministic result
  for any input order.
- **Profiles.** `balanced` (default) requires a name cue for a lone first name,
  needs six significant phone digits and space-separated IBAN groups. `strict`
  lowers the threshold to 0.25, accepts five significant digits, hyphen/dot IBAN
  groups and a lone gazetteer first name. Over-masking is the accepted cost of
  `strict`.
- **Synthetic corpus shapes.** T04's dev split added cases the brief's examples
  do not: an IBAN broken across a line break, phone numbers with a space before
  the slash (`098 / 58 42 94 20`), company names with a connector (`Koch und
  Partner GmbH`), cities with a lower-case connector (`Neunburg vorm Wald`),
  academic titles in person mentions, and street names with a preceding
  capitalised word (`Karl Heinz-Hörle-Platz`, `Dussen vanstr.`). The recognizers
  cover those shapes. The legal-form recognizer also accepts `KGaA`.
- **Legal forms and URLs in synthetic text.** German legal forms include `KGaA`
  as well as the forms the brief lists, so the organisation recognizer accepts
  `GmbH & Co. KGaA`. Presidio's URL pattern only knows public TLDs and cuts a
  scheme URL on a reserved domain (`beispiel.example`) short, so the URL
  recognizer adds a generic scheme pattern and drops post-nominal academic
  suffixes such as `B.Sc` that the bare-domain pattern would otherwise call a
  URL.
- **Offline email validation.** Presidio's email recognizer calls `tldextract`,
  whose first call may download the public-suffix list. `DeEmailRecognizer`
  keeps Presidio's pattern and replaces the validation with a local structural
  check. `tests/test_detect.py` clears the engine cache and blocks sockets while
  detecting email, IBAN and URL.
- **First-name gazetteer.** `faker.providers.person.de_DE.Provider.first_names`
  is imported once at module load (MIT, recorded in `THIRD_PARTY.md`). Months,
  weekdays and common homographs are excluded. Balanced mode reports a first name
  only next to a surname or a name cue; strict mode reports a lone one.
- **NER clean-up.** spaCy sometimes labels a URL or an email as PERSON/ORG and
  sometimes runs a name across a form line break. Detection trims person and
  organisation spans at the first newline, drops URL/email-shaped NER spans, and
  strips sentence punctuation from URLs.
- **Fixtures.** The integration tests use hand-written German enquiries in the
  same shape as T04's records, plus a regression gate over `data/synthetic/dev.jsonl`
  (80 records, 536 gold spans). On the dev split all 536 gold spans are found
  with no extra spans; dev is the tuning input and this is not an evaluation
  number. The test split is untouched until the evaluation task runs it once.
- **CI.** The German model is now needed by the tests, so CI installs the same
  pinned `de_core_news_lg-3.8.0` wheel the Makefile uses.

## Tuning and evaluation

Nothing was tuned on evaluation data. The patterns, thresholds and profile
differences were written from the brief and exercised on hand-written German
examples only. No GermEval data was downloaded or used in this task.

## Deliberately absent

- No GermEval download, no synthetic corpus generation, no LLM call, no network.
- No metrics claimed: detection has not been scored against a held-out corpus.
- No real people or companies; fixtures use common German sample names and
  example.de addresses.
