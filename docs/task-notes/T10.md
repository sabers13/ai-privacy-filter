# T10 task notes

## Scope

Write `METHOD.md` on `main` before T11 or T12 reads a test split, and make the
`METHOD.md` hash workflow executable. No detector, backend, corpus or page data
changes. No test-split number was produced in this task, so there is nothing to
report yet and nothing to tune.

## Decisions

- **One protocol, four questions.** `METHOD.md` answers the captain's four
  questions directly: per-type recall/precision, leak rate, over-masking, and
  backend sorting/drafting on placeholders. It is written in plain language
  first, then gives the exact formulas, so a reader can check every number
  without reverse-engineering code.
- **Split discipline is explicit.** Tuning uses synthetic dev (80) and GermEval
  train/dev only. Final numbers use synthetic test (160) and GermEval test
  (5,100) once per stage. The corpus hashes and per-type gold counts are pinned
  in the document and checked by `tests/test_method.py`; regenerating the corpus
  therefore fails a test instead of silently changing the evaluation.
- **Baselines are defined before results.** B0 is a shared regex rule set with
  no PERSON/ORG rules; B1 is Presidio defaults with `de_core_news_lg` and no
  custom recognizers; B2 is the product detector with a dev-selected profile.
  B0 and B1 are never tuned. B2's profile is chosen by a pre-registered
  worst-type-recall rule on dev, with over-masking and precision tie-breaks.
  If a simpler baseline wins a type, the report must say so.
- **Matching is containment, not exact boundaries.** A gold span is protected
  only when every character is inside a predicted span of a compatible type.
  Compatibility is a small fixed table (PERSON/ORG and EMAIL/URL are mutually
  compatible; everything else must match). Strict same-type recall is reported
  as a secondary column so the relaxation cannot hide type confusion. Precision
  requires a prediction to be fully inside a gold span, so over-extension is
  penalised rather than credited.
- **Leak rate audits gold, not the mapping.** The production guard only knows
  values the detector mapped, so it cannot catch a missed entity. The leak
  metric checks the exact outbound prompt against gold values, including
  digit-only phone/IBAN forms. Guard blocks and leaks are reported separately;
  the difference is exactly the missed-value path.
- **Over-masking has two units.** Enquiry-level share with a Wilson interval
  and character-level share with an enquiry-cluster bootstrap interval. Predicted
  characters outside any gold span are extra; fully false spans are counted
  separately. A baseline that replaces half the text cannot hide behind a
  sentence about precision.
- **Restore exactness has two checks.** The headline is byte-for-byte
  `restore(redact(text)) == text` over all 160 test enquiries; it measures
  fidelity, not recall. The second check is per backend on the 40 drafts:
  mapped placeholder occurrences restored, unknown placeholders, and drafts
  with no placeholders reported separately.
- **Subset is a published rule, not a hand-picked list.** Eight per category,
  taking 1-based positions 1, 5, 9, ..., 29 after sorting each category by id.
  This yields 40 unique ids, every style at least five times, and exactly the
  ids printed in `METHOD.md` section 8.2. `tests/test_method.py` recomputes the
  rule from the committed corpus, so a later edit cannot quietly swap records.
- **Triage accuracy is intention-to-treat.** Every backend gets 40 attempts;
  errors, timeouts and guard blocks count as incorrect for accuracy and are
  reported separately. Median latency uses successful calls only. The `fake`
  backend is a harness smoke test and is excluded from quality claims.
- **Hash guard is implemented, not just described.** `scripts/method_guard.py`
  computes SHA-256 over `METHOD.md`, requires a clean tracked tree and a tracked
  METHOD.md, and scans prior claims and run records. A second run of a stage
  needs `--rerun-reason`; any access after a METHOD.md change needs both the
  reason and `--method-approval` (the captain decision). It writes a durable
  claim under `results/runs/claims/` before the harness may read test data, so a
  crash does not erase the access. Malformed records fail closed.
- **No hidden reruns.** `docs/eval-reruns.md` is append-only; the harness must
  write a row before reading test data. Every row records the stage, commit,
  method hash, what changed, the reason and whether test numbers existed before
  the change. A rerun is never described as the first run.
- **LOCATION is not folded into personal-data recall.** It is not an
  `EntityType` and the detector never emits it. The report gives its gold count
  and incidental coverage separately, and says its class recall is 0 by
  construction rather than presenting a meaningless miss rate.
- **Statistics are fixed.** Wilson score intervals with the exact formula and
  `z = 1.959963984540054`; an enquiry-cluster percentile bootstrap (10,000
  resamples, seed `20261027`, linear interpolation) as a sensitivity check.
  Counts are always printed; no p-values; no pass thresholds.
- **No method change after test numbers.** The protocol, the guard and the task
  status rule all say: stop, escalate to the captain, hold. The guard enforces
  the hash mismatch; the worker enforces the hold.

## Deliberately absent

- No test-split run, no detection number, no triage number, no model call.
- No GermEval sentence, synthetic record or real personal data in the new files.
- No page data, no server access, no remote, no push, no PR.
- No change to `detect.py`, `pseudonymise.py`, `guard.py`, `triage.py`, the
  backends, the corpus or the contracts.
- No B0 parity test yet: the page try-it box lands in T14. `METHOD.md` fixes the
  shared-source requirement now so the box cannot drift into a different rule
  set later.
