# T07 task notes

## Scope

Optional Ollama path on a separate host: install, model pull, tunnel, one smoke
request and measurements. No application code changes; the BYOK backend remains
the default. Scripts live in `ops/ollama-remote/`, proof in
`results/ollama_server.json`.

## Decisions

- **Host-agnostic scripts.** The repository carries no host, IP, SSH user, key
  path or absolute home path. `tunnel.sh` reads `$AIPF_OLLAMA_SSH` and refuses to
  run without it; the host-side scripts use `$HOME` and `$XDG_CONFIG_HOME`.
- **User unit, no sudo.** Ollama extracts into `~/aipf-ollama/` (`bin/`,
  `lib/` and the runners) and runs as `aipf-ollama.service` under
  `systemd --user`, with linger already enabled on the host. `install.sh` refuses
  to start if port 11434 is held by something that is not this unit.
- **Pinned version and checksum.** `v0.40.11`, `ollama-linux-amd64.tar.zst`,
  verified against the release's published `sha256sum.txt`. If that file is ever
  unavailable, `install.sh` records the computed hash in
  `~/aipf-ollama/package.txt` and says so instead of claiming a verification.
  `AIPF_OLLAMA_SHA256` overrides the expected digest for an offline reinstall.
- **Loopback only.** The unit binds `127.0.0.1:11434`; the local tunnel listens
  on `127.0.0.1:11435` with `ExitOnForwardFailure=yes` and keepalives. No
  `0.0.0.0`, no overlay-network address, no firewall change.
- **Small-host settings.** `OLLAMA_NUM_PARALLEL=1`,
  `OLLAMA_MAX_LOADED_MODELS=1`, `OLLAMA_KEEP_ALIVE=10m`,
  `OLLAMA_CONTEXT_LENGTH=4096`, `Nice=10`, `Restart=on-failure`.
- **Smoke request mirrors the backend contract.** OpenAI-compatible chat
  completion at `http://127.0.0.1:11435/v1`, fresh UUID in
  `x-opencode-session`, `User-Agent: ai-privacy-filter/ops-smoke`, `max_tokens`
  300 and a JSON schema for category, urgency and `reply_draft`. If a build
  rejects the schema shape, the script retries with `json_object` and records
  which one answered; it does not silently accept prose.
- **No Python backend code.** T06 owns `BYOKBackend`; T07 exercises the same
  wire shape with `curl` so it neither blocks on nor duplicates that task.
- **Teardown is guarded.** `teardown.sh` needs `--yes` and is idempotent. The
  captain runs it after the demo; T07 does not.
- **Shared source file.** T05 landed `data/SOURCES.md` for GermEval; rebasing
  conflicted there. Resolved as a union: T05's dataset section is untouched and
  the Ollama and Qwen2.5 entries sit below it under "Model and runtime sources".
  No other task's content was dropped or rewritten.

## Measurements

See `results/ollama_server.json`. Host: 4 vCPU, 3.3 GiB RAM, no GPU.

- Install over ssh: 2m16s including the 1.5 GB download; checksum verified.
- Pull `qwen2.5:1.5b`: 986 MB, 1m19s.
- Tunnel: `/v1/models` lists `qwen2.5:1.5b`.
- One triage call: 193 prompt tokens, 133 completion tokens, 8.88 s, ~15 tok/s,
  schema-valid JSON.
- The same request through the real `BYOKBackend.for_ollama()` after T06 landed:
  available, no error kind, 196 prompt / 141 completion tokens in 9.2 s,
  schema-valid JSON. The backend path for T12 is therefore exercised, not just
  the raw endpoint.
- Memory: user-unit cgroup peak 1.40 GiB, serve process under 30 MiB, no swap,
  no OOM. `free` used rose by about 1.2 GiB during the call.

Honest caveats from those two calls: the model gave the wrong category both times
(`JOB_APPLICATION`, then `SUPPORT`, for a cleaning-quote enquiry), the second
answer also mixed in one Chinese sentence, and both drafts invented placeholders
that were not in the input (`[NAME_1]`, `[Buero_Reinigung_Erstellung_Genossenschaft]`,
`[Triage-Assistent Name]`). The restore step must reject unknown placeholders,
the guard must stay in front of this backend, and T12 should score local-model
categories rather than trust them. No fallback to `qwen2.5:0.5b` was needed:
under 60 s per answer and no OOM.

## Deliberately absent

- No fallback run (not triggered), no second sample, no tuning on the result.
- No sudo, no system package change, no change to other services or ports, no
  cron entry.
- No host details in the repository, the result file or the task notes.
- No teardown: the unit stays available for T12 until the captain removes it.
