# T06 task notes — LLM backends

## Scope

Ported the SaberOps worker adapters into `src/ai_privacy_filter/backends/`:
`env.py` (hermetic environment), `isolation.py` (scratch directory and process
runner), `claude_cli.py`, `codex_cli.py`, `byok.py` (OpenAI-compatible request
code from `direct_api.py`/`api_agent.py`), `quota.py` (classification from
`exhaustion.py`) and the registry. Attribution headers name SaberOps,
Apache-2.0.

Dropped as out of scope: git/worktree handling, the control plane, OmniRoute and
the gateway seam, streaming callbacks and the telemetry database.

## Decisions

- **Isolation lives in the backend, not the runner.** Each backend creates its
  own `mkdtemp` directory, writes only what the call needs (the Codex schema
  file), passes it as `cwd` (and `-C` for Codex), and removes it in `finally`.
  Tests assert the directory was empty before the call and absent afterwards.
- **Prompt on stdin everywhere.** Codex gets `-` (its documented stdin prompt);
  Claude `-p` with no prompt argument reads stdin. No prompt text is ever in
  argv.
- **Process groups.** The child starts in a new session; a timeout kills the
  group, then reads whatever partial output exists.
- **`--bare` rejected.** Installed Claude 2.1.311 documents `--bare` as reading
  auth strictly from `ANTHROPIC_API_KEY`/`apiKeyHelper`, which would replace the
  subscription login. The billing pin therefore uses
  `--settings '{"forceLoginMethod":"claudeai",...}'` with `--setting-sources ""`.
- **Codex structured output.** 0.164.0 has `--output-schema`; the schema is
  written into the scratch directory and the path passed explicitly. The reply
  is still validated locally so a model that ignores the schema cannot produce a
  malformed successful result.
- **Tool events fail closed.** Claude: a non-empty `permission_denials` fails the
  call. Codex: any `item.*` type outside `agent_message`, `reasoning`,
  `todo_list` and `error` fails the call, including unknown future types.
- **Local schema validator.** No `jsonschema` dependency for the small keyword
  subset `TRIAGE_SCHEMA` uses. The validator reports structure and path, never a
  model value.
- **Usage shape.** All real backends normalise to `input_tokens`,
  `output_tokens`, `total_tokens`, `cached_tokens`, `reasoning_tokens`. The fake
  backend keeps its T01 shape.
- **Quota reset times.** Structured epoch/ISO resets and zoned prose resets are
  used; a date without a timezone is not guessed. Routing windows, quota
  persistence and exclusions from SaberOps are dropped.
- **BYOK configuration is read at call time.** The registry constructs a backend
  before the private env file is loaded; `is_available()` and `complete_json()`
  resolve `AIPF_BYOK_*` then. An explicit empty constructor value disables the
  environment fallback, which is how `for_ollama()` avoids sending the OpenCode Go
  key to localhost.

## Verification

- `make lint` (ruff, format check, `mypy --strict src`).
- Unit and contract tests after the rebase onto main (T05): 285 passed, 1 skipped and
  3 live tests deselected. Backend tests use recorded fixtures only; argv
  assertions compare the full list.
- Live canaries ran once on 2026-10-27 under the shared live-LLM lock: 3 passed in
  24.75 s. `claude-cli` answered schema-valid JSON with no permission denial,
  `codex-cli` produced zero tool events, and `byok` (OpenCode Go,
  `deepseek-v4.1-flash`) returned schema-valid JSON with 246 reasoning tokens
  recorded. The canary token was absent in both CLI answers. Logs are in
  `results/runs/canary/`.
- One canary run was enough; no rerun is recorded.
- `scripts/scan_forbidden.py` clean; gitleaks clean.

## Deliberately absent

- No remote, push, PR or deployment.
- No real CLI transcript with real input is committed. Fixtures are hand-written
  synthetic payloads matching the native event shapes.
- No detection, pseudonymisation, service or triage prompt work; those stay in
  their own tasks.
