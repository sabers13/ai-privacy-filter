# T12 task notes

## Scope

Run the fixed 40-enquiry triage subset (`METHOD.md` section 8) through the full
pipeline (detect -> pseudonymise -> guard -> prompt -> backend -> restore) for
`claude-cli`, `codex-cli`, `byok` (OpenCode Go) and, last and optionally,
Ollama `qwen2.5:1.5b` through the T07 tunnel. Store every response with
placeholders only, add `make reproduce` / `make live` / `make page-data`, and
export the 15 page examples so T14 can start.

All inputs are synthetic and short. No real personal data, no private
infrastructure detail and no GermEval text is sent to a backend.

## Decisions

- **One triage stage, one claim.** The three primary backends share one run id
  and one method-guard claim. The optional Ollama backend runs later with the
  same run id; the guard returns `already-claimed`, so the stage is not a rerun.
  The run record gets an `extensions` row saying why the backend was added.
- **Responses live under `results/runs/<backend>/`.** The captain's brief names
  that path, so it is the canonical store: one JSON per enquiry with the raw
  text (placeholders only), parsed payload, latency, usage, prompt hash and
  response hash, plus an `index.json` with every response hash. The run record,
  metrics, report and text-free scoring stay under `results/runs/<run-id>/`.
- **Leak handling is two-sided.** The production guard runs first and blocks
  mapped values. The harness then audits the exact outbound prompt against gold
  values (normalised, plus digit-only phone/IBAN forms), so a missed value also
  stops the call. The reply is audited again before storage. A leaking prompt
  or reply is never written to disk; the record keeps the error kind, latency
  and leaked types only.
- **Intention-to-treat accuracy.** Every available backend gets the same 40
  attempts in the same order. An error, guard block or leak is incorrect for
  accuracy and is reported separately by `error_kind`. No retries and no
  fallback. Median latency uses successful calls only.
- **The prompt does not encode the corpus shortcut.** Urgency is defined
  semantically (deadline, outage, time pressure), not as "JOB_APPLICATION is
  HIGH". The report states that urgency is confounded with category in this
  corpus, so urgency-only accuracy is not independent evidence.
- **Page examples are real pipeline output.** The 15 examples are three per
  category from the fixed subset, with the stored `claude-cli` draft (fallback
  `codex-cli`). Two or three are chosen because the detector misses a gold span;
  the page shows those misses as-is. Detection spans and misses are recomputed
  from the displayed detector, so the page cannot drift from the code.
- **The rubric is manual and label-free.** Ten drafts (positions 1, 5, ..., 37)
  are shuffled with seed `20261027`, backend/model labels are removed, and one
  reviewer scores relevance, placeholder handling and German quality on 0/1/2.
  The three dimensions stay separate; there is no combined score.
- **Locks are outside the repository.** `AIPF_LOCK_DIR` points at the shared
  mission state directory. The live-LLM lock is held for every real call; the
  Ollama stage also takes the server lock. The lock is released in `finally`,
  including on a failure, and never held while idle.

## Results

Run `20261027T131500Z-triage-a1ad8ff` on commit `a1ad8ff`. One method-guard
claim, one prompt and one call configuration for every backend. All 120
primary calls returned a schema-valid reply; there were no timeouts, guard
blocks or leaks.

| backend | joint | category | urgency | median latency | restore-exact |
|---|---:|---:|---:|---:|---:|
| `claude-cli` | 28/40 (70.0%) | 35/40 (87.5%) | 33/40 (82.5%) | 5222.0 ms | 40/40 |
| `byok` (OpenCode Go) | 27/40 (67.5%) | 32/40 (80.0%) | 35/40 (87.5%) | 4785.5 ms | 40/40 |
| `codex-cli` | 25/40 (62.5%) | 32/40 (80.0%) | 33/40 (82.5%) | 6667.5 ms | 40/40 |

Honest findings, not tuned away:

- **OTHER is read as SUPPORT.** All 8 OTHER enquiries went to SUPPORT for
  `byok` and `codex-cli`; `claude-cli` got 3 of 8 right. The OTHER templates
  are general questions that look like support requests, so this is a real
  label-boundary problem in the corpus as well as a model error.
- **NORMAL is sometimes read as HIGH.** 5 (`byok`) and 7 (`claude-cli`,
  `codex-cli`) of the 24 NORMAL enquiries were labelled HIGH. Urgency is tied
  to category in this corpus, so urgency-only accuracy is not independent
  evidence.
- **Drafts are clean but not uniform.** Every draft restored exactly and no
  draft contained a gold value or an unknown placeholder. 7 (`byok`), 1
  (`claude-cli`) and 11 (`codex-cli`) drafts used no placeholder at all, which
  is reported separately because it is trivially exact.
- **Rubric (claude-cli, 10 drafts, one reviewer).** Relevance 2.0 (range 2-2),
  placeholder handling 2.0 (2-2), German 1.6 (1-2). One draft invented a
  forwarded-to-support action. The four 1s are gender-slash address forms such
  as "Sehr geehrte/r", which are understandable but not clean register.
- **Latency has a long tail.** Medians are 4.8-6.7 s, but the maximum was
  56.8 s (`claude-cli`) and p95 was 33.2-33.2 s for the CLI backends. One
  machine and one network path; not a benchmark.

from the stored responses.
